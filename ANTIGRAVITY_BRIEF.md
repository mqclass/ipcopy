# Бриф для Antigravity / Gemini

Привет! Помоги провести **техническое ревью и придумать улучшения** для клиентского Fabric-мода Minecraft. Нужны конкретные, реалистичные идеи и безопасный план реализации — без выдумывания API и без изменения сторонних JAR-файлов.

## Что это за мод

- Название: **IP Copy by mqclass**.
- Minecraft: **1.21.11**.
- Загрузчик: **Fabric**.
- Основная задача: когда сервер присылает в чат IP-адрес (особенно в ответ на `/auth player <ник> info`), мод находит валидный IPv4 и добавляет справа кнопку **`[Скоп. IP]`**. Клик копирует именно этот адрес в буфер обмена.
- Целевая аудитория: модераторы сервера.

## Текущие возможности

- Ищет строгие IPv4-адреса, проверяя каждый октет в диапазоне `0..255`.
- Не считает IP-адресом версии наподобие `1.21.11`.
- Сохраняет стили исходного сообщения и обрабатывает строки по отдельности: у каждой строки с IP появляется своя кнопка.
- Не добавляет повторные кнопки, если сообщение уже прошло обработку.
- Ограничивает обработку: сообщение максимум 32 767 символов, до 64 IP на сообщение.
- Не выполняет HTTP-запросы, не пишет IP в файлы, не создаёт фоновые потоки и не хранит историю IP.
- Команды:
  - `.ipcopy` — локальная справка и текущий статус;
  - `.ipcopy test` — демонстрация с тремя разными адресами игрока `DiNoKy`;
  - `.ipcopy toggle` — включить/выключить автоматическую обработку;
  - `.apf <ник>` — отправить серверу `/auth player <ник> info`.
- Есть совместимость со SpaceModeration 3.5.1: наши dot-команды перехватываются до её обработчика, а раздел IP Copy добавляется в `.help`.

## Важное ограничение SpaceModeration

SpaceModeration 3.5.1 — сторонний обфусцированный мод без исходного кода. Его JAR **не нужно распаковывать, перепаковывать или встраивать в наш мод**. Интеграция допустима только через безопасимые необязательные mixin-инъекции/публичные клиентские API, чтобы моды оставались отдельными и обновлялись независимо.

У SpaceModeration есть собственный обработчик команд с точкой: он отменяет исходящее сообщение до стандартного Fabric-события. Поэтому для `.ipcopy` и `.apf` уже сделана необязательная инъекция в его `DotCommandHandler`.

## Что нужно от тебя

1. Проведи ревью архитектуры и назови реальные риски для Fabric 1.21.11: mixin-конфликты, повторная обработка чата, совместимость с другими модами, неправильное использование клиентских API, утечки приватных данных и производительность.
2. Предложи **не более 5** самых ценных улучшений. Для каждого укажи:
   - пользу для модератора;
   - сложность: низкая / средняя / высокая;
   - затрагиваемые классы;
   - как проверить результат в игре;
   - риски и способ отката.
3. Отдельно придумай небольшой и аккуратный GUI. Он должен быть действительно полезен, а не «окном ради окна». Например, экран настроек с toggle, настройкой показа кнопок, краткой инструкцией и кнопкой локального теста. Предложи UX-макет в тексте и подходящий путь открытия, например `.ipcopy gui` или Mod Menu.
4. Проверь идею истории недавно скопированных IP с точки зрения приватности. По умолчанию она **не должна** хранить IP на диске и не должна отправлять их в сеть. Если такая функция вообще нужна, предложи безопасный opt-in дизайн.
5. Предложи, как сделать интеграцию со SpaceModeration более устойчивой к обновлениям, не модифицируя её JAR и не полагаясь на нестабильные обфусцированные имена сильнее необходимого.
6. Дай приоритетный план из 3–5 шагов. Не пиши огромный рефакторинг без причины.

## Правила ответа

- Отвечай по-русски.
- Не утверждай, что метод/API существует, если не уверен: помечай это как «нужно сверить с yarn/Fabric API 1.21.11».
- Не предлагай отправлять, логировать или сохранять IP без явного согласия пользователя.
- Не предлагай обход прав сервера, античита, модерации или получение чужих данных вне уже отображаемого сервером чата.
- Не предлагай объединять JAR SpaceModeration и IP Copy.
- Сначала дай краткий вывод, затем таблицу улучшений и конкретный план.
